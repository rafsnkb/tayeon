- **브랜치 워크플로우 확정**: `main`=개발, `live`=프로덕션(App Hosting이 `live`에서 배포). 새 기능은 `main`에서 작업 후, 완료되면 `main`→`live` fast-forward merge + `firebase apphosting:rollouts:create <backend> --git-branch live`로 배포. **`live`엔 절대 직접 푸시하지 말 것**
- 배포 과정에서 발견/수정한 실제 버그:
  - `tsconfig.json`/`eslint.config.mjs`가 `functions/`(미사용 스캐폴드)까지 타입체크 대상에 포함시켜서 App Hosting 빌드가 실패함 — `admin`과 마찬가지로 `functions`도 exclude에 추가해서 해결

  - 관리자 앱 구글 로그인이 "로그인에 실패했습니다"로 바로 실패 — Firebase Auth "승인된 도메인" 목록에 새 App Hosting 도메인들이 없어서였음(Identity Toolkit Admin API로 직접 추가: `tayeon-admin--...hosted.app`, `tayeon--...hosted.app`, `tayeon.kr`)

- **관리자 페이지는 커스텀 도메인을 붙이지 않기로 결정 (2026-09-12)** — 기본 `*.hosted.app` 주소를 계속 사용. 아직 안 한 것: 포트원 결제 연동(아래 참고)

## 1. 지금 완성된 것 (실제로 동작 확인됨)

**전체 플로우**: 카카오 로그인 → (신규면) 가입/약관동의 → 온보딩 팝업 → 타로 채팅(멀티 대화방) → 코인 소진형 리딩(스프레드 + 사주/자미두수 옵션) → 내 정보 설정 → 탈퇴

### 인증/가입
- 카카오 로그인 → Firebase 커스텀 토큰 교환 (`/api/auth/kakao/callback`)
- 신규/기존 회원 분기 (Firestore 문서 존재 여부로 판별)
- 가입 화면(`/signup`): 닉네임 설정 + 이용약관/개인정보처리방침 동의(팝업 모달) → 무료 코인 500 지급
  - **생년월일시 선택 입력 추가 (2026-09-12)**: 가입 후 `/me`에서 따로 입력하는 수고를 덜기 위해, 닉네임 아래에 `/me`와 동일한 생년월일시 폼(성별/양음력/생년월일/시간/시간모름/자시법)을 선택 입력으로 추가. 생년월일·성별 둘 다 비우면 건너뛰고 나중에 입력 가능, 하나만 채우면 제출 차단(반쪽 데이터 방지). `POST /api/user/signup`이 선택적 `birthInfo`를 받아 닉네임과 한 번에 저장(`/api/user/birth-info`와 동일한 검증 로직 재사용)
- 탈퇴 기능 (`/me`에서, Firestore 문서 + Firebase Auth 계정 삭제)

  - ⚠️ **검증 결과가 애매함**: 같은 질문(쓰리카드, 새 대화방/히스토리 없음)으로 수정 전/후 프롬프트를 실제 API로 각 8회씩 재현 시도 — **수정 전 프롬프트도 0/8 거절**(전부 정상 해석 제공). 즉 단일 턴·깨끗한 상태에서는 기존 규칙만으로도 이미 대부분 정상 동작해서, 실사용에서 실제로 왜 거절이 나왔는지 재현하지 못함(대화 히스토리가 있는 방이었는지, 문구가 스크린샷과 미묘하게 달랐는지 등 미확인 변수 있음). 이번 조치는 "밑져야 본전"인 방어적 보강 — 위험 없이 명시성만 높인 것이라 유지하되, 근본 원인은 09-09에 남겨뒀던 "구조적으로 남은 위험"(모델이 드물게 규칙을 어기는 경우 서버 검증 없이는 못 막음)과 같은 종류일 가능성이 있음
