# RAFS 프로젝트 기획 정리

> 최종 업데이트: 2026-09-07 (대화 기준 정리본)

---

## 1. 프로젝트 개요

- **목표**: AI 기반 운세 서비스 개발 (한국 시장 타겟)
- **메인 서비스**: 타로 (질문 기반, 저가 포지셔닝)
- **서브 서비스**: 사주(saju), 자미두수(紫微斗數), 궁합(타인 생년월일시 입력 기반)
- **개발 방식**: AI 바이브 코딩 (개발자 아님, 코딩 지식 없음 — UI 테크니컬 디자이너 배경)
- **계산 엔진**: 만세력/사주/자미두수는 자체 구현이 아닌 **외부 API·오픈소스 라이브러리 활용** (예: lunar-javascript 기반 계산기 등 존재 확인)

---

## 2. 시장 현황 (조사 기반)

- 국내 AI 타로/사주 시장은 **이미 포화 상태 (레드오션)**
  - 대표 경쟁사: **헬로우봇** (누적 다운로드 1위, 판매 40만 회, 사주+타로+궁합+작명 종합 플랫폼)
  - 그 외 다수의 AI 타로 앱 존재 — "질문 입력 → AI 스프레드 추천 → 해석" 구조가 이미 업계 표준
  - **SAJU** 앱은 2010년부터 15년 이상 운영 중인 장수 앱
- **자미두수는 국내 상업 서비스가 거의 없음** — 개인 개발자의 취미/사이드 프로젝트 수준(예: 무료 웹앱)으로만 확인됨. 상용 앱(헬로우봇, SAJU)도 메인 메뉴로 잘 다루지 않음 → **시장 수요 자체가 얇다는 신호**
- 기술 진입장벽이 낮아(LLM API + 카드 로직) 신규 유사 앱이 계속 쏟아지는 구조

## 3. 가격 전략 논의

### 3-1. "질문당 200원" 검토 결과
- 헬로우봇 실제 가격: 하트 25개 = 5,500원 → **1하트 ≈ 220원**. 리뷰상 타로/사주 1회에 하트 다수 소모 → 실질 리딩 1회 비용은 **수천 원대**로 추정
- 월 구독 9,900원 모델도 병행 운영 중
- **200원은 시장가 대비 현저히 낮음** — 문제점:
  1. 애플 IAP 최소 단가 정책상 정확히 200원 단위 설정이 어려울 가능성 (최소 티어 400원~1,500원 수준 이력)
  2. 스토어 수수료 30%(소규모 개발자 프로그램 시 15%) 차감 시 실수령 140~170원
  3. LLM API 원가는 문제 아님 (추정 수 원~10원 수준, 정확한 실측치 아님)
  4. **진짜 문제는 CAC(고객획득비용)** — 순이익 140~170원/회 기준, CAC 1,000원만 가정해도 6~7회 이상 재구매해야 손익분기. 이 카테고리 특성상 비현실적

### 3-2. 전 라인업(타로/사주/자미두수) 동일 저가 전략으로 결정
- 장점: 메시지 일관성 확보, 업셀 갈등(저가 유입 vs 고가 서브서비스) 해소
- 리스크:
  1. 업셀을 통한 객단가 상승 논리가 성립 안 됨 → 서브 서비스의 목적을 **매출이 아닌 리텐션/체류시간**으로 재정의할 필요
  2. 사주 카테고리는 전통적으로 "가격=신뢰(권위)"로 인식되는 경향이 있어, 지나친 저가가 오히려 신뢰도·전환율을 깎을 가능성 (정량적 근거는 없는 정성적 우려)
  3. 객단가로 승부가 안 되면 결국 **트래픽 볼륨 게임** → 유료 마케팅(CAC)으로는 회수 불가 → **바이럴/유기적 성장 의존도가 매우 높아지는 구조**로 귀결

## 4. 서비스 라인업 논의

- 최초 구상: 타로 단일 / 타로+사주 / 타로+사주+자미두수 (3안), 궁합 포함 시 총 5개 서비스 조합
- 우려사항:
  - 사주와 자미두수는 각각 **정답이 있는 계산 문제** (타로는 해석형이라 오답 개념이 약함) → LLM에 직접 계산시키면 오류 리스크 있으나, **외부 API/라이브러리 사용으로 대부분 해소**
  - 단, 라이브러리 결과의 정확성 검증(알려진 정답 케이스 대조)은 별도로 필요
  - 궁합 기능은 **제3자(타인) 개인정보 입력**을 수반 — 개인정보보호법 관련 고지/약관 처리 필요 가능성 (법적 확답 아님, 검토 필요 항목으로 기록)
- **최종 방향**: 타로를 메인으로 마케팅, 사주·자미두수·궁합은 서브 서비스로 포지셔닝 (기술적 개발 순서/출시 순서는 별도 결정 필요 — 아직 확정 안 됨)

---

## 5. 미해결 / 다음에 논의 필요한 사항

1. "저가"의 **구체적 가격 수치** (사주/자미두수 포함 전 라인업)
2. 서브 서비스(사주/자미두수/궁합)의 역할을 **매출 채널**로 볼지 **리텐션 채널**로 볼지 명확화
3. **바이럴/공유 유도 설계**가 핵심 성장 채널이 될 가능성이 높음 → 궁합 결과 공유, MBTI식 캐릭터 카드 등 공유 유도 UX 설계 필요
4. 마케팅비(유료 광고) 집행 여부 및 규모 — 저가 전략과의 정합성 재검토 필요
5. 개발 순서: 전 라인업 동시 개발 vs 타로 우선 출시 후 데이터 기반 확장 — 아직 사용자 쪽 최종 의사결정 대기 중
6. 사주/자미두수 계산 라이브러리·API의 정확도 검증 방법 및 기준
