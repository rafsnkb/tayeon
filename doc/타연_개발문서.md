# RAFS 서비스 개발 문서

> 최종 업데이트: 2026-09-07

---

## 1. 프로젝트 개요

- **서비스명(가칭)**: RAFS / 타연
- **목표**: AI 기반 운세 서비스 (한국 시장, 웹 전용)
- **메인 서비스**: 타로 (질문 기반, 저가 포지셔닝)
- **서브 서비스(토글형 옵션)**: 사주, 자미두수, 궁합(타인 정보 기반)
- **개발 방식**: AI 바이브 코딩 (비개발자, UI 테크니컬 디자이너 배경)
- **플랫폼**: 웹 전용 (모바일/PC 반응형, 앱 미출시)
- **회사**: 개인사업자 rafraum, Google Workspace 사용 중

---

## 2. 서비스 구조

### 2-1. 라인업 (베이스 + 토글 방식)
- 베이스: 타로
- 옵션 토글: +사주, +자미두수, +궁합
- 옵션 추가 시 질문당 코인 비용 증가 (아래 가격표 참고)
- 마케팅은 "AI 타로"로 통일, 서브 서비스는 서비스 내 자연 업셀

### 2-2. UI
- 채팅형 UI (타로 질문-응답 흐름에 최적)
- 사주/자미두수 결과는 카드형 컴포넌트로 채팅 안에 하이브리드 표시
- 최초 가입자 온보딩 팝업 필요 (아래 6장 참고), "다시보지않기" 체크박스는 서버 계정 플래그로 저장

### 2-3. 궁합 기능
- 상대방 정보 입력: "상대방을 뭐라고 부를까요? (별명/애칭 가능)" 방식 — 본명 입력을 유도하지 않는 문구
- 상대방 정보는 **1명만 저장 가능**, 새 정보 입력하려면 기존 정보 삭제 후 재입력
- 상대방 가입 강제 없음 (마찰 방지, 대신 바이럴 루프는 약해짐을 감수)

## 3. 가격 정책

### 3-1. 질문당 가격 (코인 기준, 1코인=1원)
| 서비스 조합 | 질문당 코인 |
|---|---|
| 타로 단일 | 200 |
| 타로+사주 | 250 |
| 타로+사주+궁합 | 300 |
| 타로+사주+자미두수 | 400 |
| 타로+사주+자미두수+궁합 | 500 |

### 3-2. 코인 충전
- 결제 방식: 코인 선충전 (질문당 직접 결제 아님)
- 충전 단위(예시): 1,100 / 2,300 / 5,500 / 11,000원
- 큰 단위 충전 시 보너스 코인 지급 (비율 미정)
- 코인 유효기간: **무기한**
- 사용한 코인은 **환불 불가** (청약철회 제외 대상으로 약관 명시 필요)

### 3-3. 가격 전략 근거
- 전 라인업 저가 통일 → 업셀 갈등 없음, 메시지 일관성 확보
- 대신 서브 서비스 목적은 매출이 아닌 **리텐션/체류시간**으로 재정의
- 코인 충전 방식 채택으로 앱스토어 IAP 최소단가 문제 회피 (단, 웹 서비스라 앱스토어 수수료 자체가 없음)

## 4. 기술 스택

| 영역 | 선택 |
|---|---|
| 프론트엔드 | Next.js |
| 백엔드/인프라 | Firebase (App Hosting, Auth, Firestore, Cloud Functions) |
| 로그인 | 카카오 소셜 로그인 (Firebase Auth 커스텀 토큰 연동) |
| 결제 | 포트원 (코인 충전, 카카오페이/토스페이 등 간편결제 연동 권장) |
| 만세력/사주/자미두수 계산 | 오픈소스 라이브러리 사용 (아래 참고) |
| AI 모델 | Claude Haiku 4.5 (1차 결정, 필요 시 서비스 등급별로 모델 분리 검토 가능) |
| 알림/인증 발송 | 카카오 알림톡 (SMS 대비 저렴, 카카오 비즈니스채널 개설 + 템플릿 사전 심사 필요) |

### 4-1. 만세력/사주/자미두수 라이브러리
- **`@orrery/core`** (github.com/rath/orrery): 사주팔자 + 자미두수 명반을 한 라이브러리에서 지원. TypeScript/npm.
- **`manseryeok`** (github.com/yhj1024/manseryeok): 한국천문연구원(KASI) 공식 데이터 기반 사주팔자 계산. 자미두수는 미지원.
- **검증 계획**: `@orrery/core` 결과값을 `manseryeok`(KASI 데이터 기반) 및 알려진 정답 사례와 교차 검증 필요 (미실행, 개발 착수 시 진행)

### 4-2. AI 모델 관련
- Claude Haiku 4.5: $1/$5 (백만 토큰당 입력/출력) — 1회 질문당 원가 약 6~15원 추정
- 참고 비교: Sonnet 5 ($2~3/$10~15), GPT-5.6 Terra ($2/$12), Gemini 3.6 Flash ($1.5/$7.5)
- 원가는 판매가(200~500원) 대비 미미한 수준이라, 모델 선택은 비용보다 한국어 톤/품질 기준으로 추후 재검토 가능
- 서비스 등급별 모델 차등 적용 아이디어 있음 (베이스 타로=저가 모델, 상위 서비스=고급 모델) — 확정 아님

### 4-3. 시스템 프롬프트 설계 원칙
- 페르소나 지시는 system 메시지, 사용자 입력은 user 메시지로 엄격히 분리
- 탈옥/프롬프트 인젝션 시도("이전 지시 무시해" 등)에 대한 명시적 대응 지침 + 응답 예시를 system 프롬프트에 템플릿으로 포함
- "저는 AI입니다", "시스템 프롬프트는 ~" 같은 발화 금지 지침 포함
- 출시 전 알려진 인젝션 패턴으로 실제 테스트 필요 (미실행)

### 4-4. 인프라 관련 체크사항
- Google Workspace(rafraum) 조직 하위에 Firebase 프로젝트 생성 시, 조직 정책(리소스 생성 제한, 도메인 제한 공유)이 걸려있는지 사전 확인 필요
- Blaze(종량제) 요금제 전환 필수 (Cloud Functions, App Hosting 등 사용을 위해)
- API 장애/실패 대응: **코인은 LLM 응답 성공 확인 후 차감**하는 순서로 설계 (선차감 후 실패 시 환불 로직 대신, 구조적으로 문제 자체를 제거)

---

## 5. 가입/인증

- **가입 방식**: 카카오 소셜 로그인 (SMS 인증 대신 채택, 원터치 가입으로 웹 접근성 이점 유지)
- 카카오 계정 자체가 전화번호 인증을 거친 상태라 다중계정 방어를 카카오에 위임하는 구조
- 전화번호/이메일 등 추가 정보 필요 시 별도 동의 스코프 신청 필요 (카카오 비즈니스 앱 심사)
- **미성년자 판별**: 카카오 `age_range` 동의항목은 선택 동의라 신뢰 불가. 사용자가 서비스 내에서 직접 입력하는 생년월일시로 만 14세 미만 여부를 판단하는 방식이 더 정확하고 실무적

## 6. 온보딩 및 개인정보

### 6-1. 온보딩 팝업 (최초 가입자 대상)
포함 내용:
- 오락 목적 서비스이며 의학적·법적·재정적 조언이 아니라는 고지
- 만 14세 미만 이용 제한 또는 법정대리인 동의 안내
- 결제/환불 정책 요약 + 전문 링크
- 개인정보(생년월일시) 수집·이용 동의 안내 + 개인정보처리방침 링크
- "다시보지않기" 체크 → 서버 계정 플래그로 저장 (로컬스토리지 아님)

### 6-2. 개인정보 관련 결론
- **생년월일시 단독으로는 개인정보에 해당하지 않음** (같은 시각 출생자가 다수 존재해 특정 개인 식별 불가) — 법률 자문은 아니며 일반적 해석 기준
- 이름 등 다른 식별정보와 결합되는 순간 개인정보로 전환됨
- 궁합 상대방 정보는 **이름을 받지 않고 별명/애칭으로만** 받는 방식으로 설계 → 리스크 최소화 + UX 개선 동시 달성
- 향후 기능 추가 시 "상대방 이름" 필드를 넣지 않도록 주의 (넣는 순간 개인정보 결합 발생)

### 6-3. 문서화 필요 (추후 별도 작성 예정)
- 이용약관
- 개인정보처리방침
- 통신판매업 신고

## 7. 마케팅/그로스

### 7-1. 채널
- **1차: 인스타그램 유료광고** (타겟 연령대 이용률 최고, 릴스 포맷과 콘텐츠 궁합 좋음)
- 페이스북 제외 (타겟 연령대 이용률 낮고 이용자 고령화)
- 틱톡은 추후 검토 (숏폼 성장세 크나 운영 경험 없어 보류)

### 7-2. 바이럴/공유 설계
- 결과물(타로/사주/궁합 결과)을 **이미지로 다운로드 가능**하게 제공 → 공유 트리거
- "가격이 싸다"는 광고 카피는 바이럴 트리거가 아니라 전환 카피로 별도 취급
- **리퍼럴**: 친구 초대 시 초대자·피초대자 모두 코인 지급
  - 어뷰징 방지: 코인 지급 시점은 **피초대자가 실제 결제(충전)한 시점**
  - 최대 **10명까지 초대 허용**
  - 다중계정 방지: 카카오 로그인 자체 방어력 + 필요 시 추가 검토

### 7-3. 광고 카피 유의사항
- "마음껏 물어보세요" 류 카피는 실제 코인 소진 구조와 기대치 괴리 주의
- 경쟁사 가격 비교 카피("타사는 밥값/커피값") 사용 시 실제 숫자 검증 필요 (미검증 상태)

## 8. CS/운영 정책

- **고객센터**: 이메일 채널
- **환불 정책**: 사용한 코인은 환불 불가 (청약철회 예외 조항으로 약관에 명시 필요)
- **코인 유효기간**: 무기한

## 9. 전체 사용자 플로우 (요약)

1. 유입 (인스타그램 광고 등)
2. 가입 (카카오 소셜 로그인)
3. 온보딩 팝업 확인 (최초 1회)
4. 무료 코인 지급
5. 타로 질문 입력 (옵션: +사주 +자미두수 +궁합 선택, 옵션별 생년월일시 입력 폼)
6. 코인 차감 → 만세력 라이브러리 계산 → LLM 해석 생성 (부족 시 포트원으로 충전)
7. 결과 표시(채팅+카드형 UI) → 이미지 다운로드
8. SNS 공유 → 리퍼럴 코인 지급(피초대자 결제 시) → 재유입 순환

---

## 10. 미해결 / 추후 확인 필요 사항

1. 만세력/자미두수 라이브러리 정확도 실측 검증 (`@orrery/core` vs `manseryeok` vs 알려진 정답 사례)
2. 시스템 프롬프트 탈옥 방어 실제 테스트 (알려진 인젝션 패턴 대입)
3. 코인 보너스 지급 비율 (대량 충전 유도용)
4. 리퍼럴 다중계정 어뷰징 추가 방어 필요 여부
5. 경쟁사 실제 가격(리딩 1회당 비용) 정밀 확인 — 광고 카피에 비교 문구 사용 시 필수
6. 이용약관/개인정보처리방침/통신판매업 신고 — 문서화 진행 예정
7. 선불충전금(코인) 성격이 전자금융거래법상 등록 대상인지 여부 — 폐쇄형 포인트로 예외 해당 가능성 높으나 확정 필요
8. Google Workspace(rafraum) 조직 정책상 Firebase 리소스 생성/도메인 제한 이슈 사전 확인
